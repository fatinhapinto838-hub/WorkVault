# 最终成果栏目（1.2.0）

左侧「最终成果」将每个项目的交付文件独立集中展示。可以按项目和文件名称搜索、选择项目、分页浏览，预览、使用默认应用打开、导出和移出。空项目也有入口，不显示虚构成果。

## 日常使用

1. 打开 WorkVault，点击左侧「最终成果」。
2. 选择项目，点击「添加成果」，从该项目已归档文件中勾选并确认。待确认文件须先核对归属。
3. 添加时固定当前版本。若要收录历史版本，在文件详情的版本历史中点击「收录为项目最终成果」，再选择所属项目。
4. 后续编辑会生成新的工作版本，栏目仍保留之前选中的版本。重新选择该文件可更新本项目的成果版本。
5. 点击「移出」仅取消栏目中的收录，文件、项目关联、原文件和历史版本均保留。文件删除至回收站时暂不展示，恢复后原收录重新显示。

每个项目详情也有独立「最终成果」区域，可直接查看或添加。同一个实体文件在两个项目中可以分别选择不同版本；相同标题的项目仍按各自 ID 区分。

## 历史成果收录依据

2026-11-17 的一次性历史整理使用桌面应用提供的真实任务记录：只解析用户可见最终回复中的明确本地文件链接，核对项目任务 ID、完整来源路径、原文件 SHA-256 及已入库版本。收录每个项目最近一次可见的明确交付回复中、能核验的具体文件，不汇总所有旧回复，不按“最终/final”等文件名推测。

这次整理不是账户自动同步，也没有让 WorkVault 获得读取其他任务的公开账户权限。软件后续新增收录由用户操作；不会宣称持续连接 ChatGPT。

只有目录链接且缺少可核实的具体执行清单、缺失文件、原文件已变化且没有匹配的已存版本、缺少明确交付链接的项目，保留手动选择入口。目录中的源代码、依赖和预览缓存不会因目录被提及而全部自动标为最终成果。已核验「交付」只表示文件被任务明确交付，不保证其学术、工程或内容质量。

## 数据与维护

数据库 schema 4 新增 `project_deliverables`：项目、文件、固定版本、交付显示名称、证据类型/说明、来源路径和收录时间。复用原有只读文件实体，不另存一套文件。

升级时将已有明确的最终标记迁移为收录；无标记的文件不推断。合并项目保留双方版本，拆分时连同所选文件的收录一起移动。重新关联项目时只移除失去项目关联的收录。

备份、恢复和迁移携带数据库中的收录关系。1.0.0 不支持 schema 4；升级后请使用 1.1.0 或更新版本。若需要回退，先退出应用，再使用升级前的完整备份或专门保留的元数据恢复点，由维护人员核对版本后操作，避免直接覆盖当前库。

AI、目录监控和收费 API 不会因使用本栏目而启用。


## 时间排列（1.2.0）

项目分组按项目内最新成果时间倒序排列，项目内文件也按时间倒序分页。已核实的真实任务交付时间优先；没有交付时间的手动收录使用真实收录时间，并显示「收录时间／交付时间未记录」。不使用文件名推断日期，不把导入时间或收录时间冒充交付时间。日期显示年份，时区为北京时间 Asia/Shanghai。

交付时间与收录时间分别保存。手动重新选择同一项目中的相同版本会保留已核实交付时间；改选新版本时不会继承旧版本或其他项目的交付时间。移出、恢复、合并、拆分、备份和迁移保留相应日期信息。

Schema 5 新增 `delivered_at`、`time_source` 和时间排序索引，读取旧库时不凭空填入交付时间。历史任务日期只在明确授权的来源核验流程中补充；普通 RPC 不接受伪造「官方交付时间」。旧 1.1.0 无法打开升级后的 schema 5，请使用 1.2.0 或更新版本。
