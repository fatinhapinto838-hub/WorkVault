# 文件库存储与完整性说明

版本：WorkVault 1.0.0，数据库迁移版本 3。此文档对应实际 Swift Store / DB 实现。

## 本地目录

用户选定的文件库目录包含：

| 路径 | 内容 |
| --- | --- |
| `workvault.sqlite` | 项目、文件、版本、来源、授权、设置、导入任务、使用统计和手动建立的检索索引 |
| `blobs/<SHA-256 前两位>/<完整 SHA-256>` | 按内容寻址的文件实体；相同二进制内容只保留一份 |
| `working/<文件 ID>/<文件名>` | 用户明确执行“默认应用打开”后建立的可编辑工作副本 |
| `previews/<版本 ID>/` | 打开历史版本时建立的只读副本 |
| `tmp/` | 未提交导入临时文件、受限制的压缩包解压目录 |
| `indexes/` | 可选本地索引资源；AI 向量当前也保存在 SQLite 中 |
| `logs/` | 本地日志保留目录，界面操作日志主要在 SQLite 中 |
| `backups/` | 用户可选择的手动备份位置，系统不自动创建定时备份 |

应用会将文件库目录权限设为仅当前用户访问。文件实体默认只读，外部编辑发生在 `working` 中。SQLite 使用 WAL、外键、事务及 `synchronous=FULL`。不要在应用运行时手工移动数据库、WAL、SHM 或实体文件；使用界面的迁移或手动备份功能。

## 导入事务

导入依次检查普通文件和可读权限，按 1 MiB 分块复制到临时文件，计算 SHA-256，刷新写入，重新校验临时文件和源文件，再将内容原子移动到实体目录。数据库记录在实体校验完成后才提交。复制错误不会删除原文件；数据库事务失败时，应用会清除本次新建且未被数据库引用的实体。

相同内容再次导入会复用文件实体和当前文件记录，增加项目关联或来源记录。同名但内容不同的文件独立登记。只有明确执行新版本操作，才会把新的内容关联为旧文件的版本。正常导入不会仅凭名称建立版本关系。

普通下载、专用收件目录中无法确认任务来源的文件进入待确认收件箱。用户明确确认后才进入正式档案。收件箱内的“忽略”或文件回收站状态均不删除原下载文件；实体仍保留，以便恢复。

应用中断后，启动恢复会把尚处于运行状态的导入任务标记为“已中断”，保留已经提交的文件，并清理本应用在 `tmp` 中留下的未提交临时项。不会将未完成的复制标记为正常成果。

## 任务来源与标题

项目显示标题与 Work 原始标题分别保存。可靠的会话标识通过项目来源表关联；重复标题不会自动合并。按同一会话标识收到新的标题时，可以更新原始标题和来源信息，保留用户已修改的显示标题。

手动合并项目会保留来源任务记录；后来再次导入原任务标识时，仍会关联到合并后的项目。拆分文件是用户明确的项目关系调整，不会复制文件实体。

官方导出仅解析本地提供的数据，不登录 ChatGPT，不请求私人接口。无法区分 Chat 与 Work 的导出会话被登记为待确认候选项目（`source_confirmed=0`），不计入正式 Work 项目总数。附件元数据和 `sandbox:/mnt/data/` 引用只形成“需要补充原文件”的索引，不代表附件已经下载。应用不伪造缺失附件。

## 专用目录任务清单

要让本地成果同时携带可靠的用户提供标题，可以将文件和一个以 `.workvault.json` 结尾的清单一起保存到用户授权的专用目录。例如：

```json
{
  "workvault": 1,
  "title": "CCUS 岩石物理研究报告",
  "conversation_id": "可选的真实任务标识",
  "source_url": "https://chatgpt.com/c/真实会话标识",
  "files": ["outputs/报告.pdf", "outputs/计算表.xlsx"]
}
```

`files` 必须是相对于清单所在目录的普通文件路径。禁止绝对路径、`..`、符号链接和超出授权目录的文件。清单中的标题是“用户提供任务清单”来源，不会冒充独立连接 ChatGPT 后读到的标题。缺少会话标识时，每份新清单不会仅凭相同标题自动合并。

监控使用低频扫描，文件的大小和修改时间连续稳定后才接收。临时下载扩展名会被忽略。下载目录在首次授权时建立已有文件基线，避免把全部历史下载当成新 Work 成果。修改和重命名通过指纹与内容哈希处理；不修改或删除监控目录中的原文件。

## ZIP 安全边界

手动 ZIP 导入会保留压缩包本身，并导入安全解压后的普通文件；不会递归解压内嵌 ZIP。ZIP 中的来源路径记录为 `原压缩包路径!/成员相对路径`，不会声称临时解压位置是原始来源。

当前限制：压缩文件不超过 2 GiB，解压总体积不超过 1 GiB，条目数量少于 10,000；拒绝多卷、ZIP64、加密条目、路径穿越、符号链接、非 UTF-8 文件名、压缩比异常或前导连字符成员名。Office 简化预览使用相同路径校验，并施加更低的内容体积限制。

解压逐成员运行本机 `unzip -p`，将成员名中的模式字符转义后精确匹配，只把字节流写入应用自行创建的普通文件。实际输出逐块计数，不信任中央目录声明的体积；超出单成员声明或总体积限制会立即终止子进程并报错。不会让压缩包控制外部写入路径。

## 外部编辑与版本

“使用默认应用打开”会复制当前版本到受管理工作副本。实体与旧版本不被覆盖。编辑后，用户执行检查修改，再选择登记新版本或放弃工作副本。尚未登记的工作副本不应当被视为已经纳入版本历史的成果。

手动增加版本时，如果二进制内容相同，不产生重复版本。恢复旧版本会产生一条新的恢复版本记录，保留恢复前的当前版本。历史版本打开为只读副本。

## 备份、恢复与迁移

备份为 `.wvbackup` 目录，含数据库一致性快照、文件实体、版本关系和 SHA-256 清单。快照会切换为独立的 DELETE 日志格式并显式关闭，避免依赖源目录的 WAL/SHM 文件；正常运行的文件库仍使用 WAL。文件库外的工作副本和原始下载不作为已登记版本备份。AI 索引可选；不含索引时，备份数据库会删除索引内容并执行 VACUUM。API Key 仅在 Keychain 中，不写进普通备份。

恢复先校验清单，再复制到尚不存在的新目录，运行文件实体和数据库检查，不覆盖当前库。恢复完成后可明确选择切换到该已有库。迁移采用先复制、校验再切换的流程，旧文件库保留。

已有文件库的数据库结构若比本应用更新，应用会在只读检查阶段拒绝打开，不会先降级修改。实体读取和完整性检查会验证相对路径、`blobs/` 前缀及符号链接边界；存储磁盘不在线时显示不可用，不把离线误作删除。

## 当前实现边界

普通搜索使用已登记的文件名、标签和项目标题，不会默认提取全文。手动建立索引后才提供内容检索。Office 界面是 XML 内容的简化预览；Excel 共享字符串、公式、图表或复杂排版不能保证还原，请用本机 Office 查看原始文件。

本应用不提供文件实体的永久垃圾回收；回收站和历史版本保留空间是有意的可恢复行为。文件库应通过经过校验的手动备份长期保存。不要把未经备份的实体目录当作可随意清理的缓存。
