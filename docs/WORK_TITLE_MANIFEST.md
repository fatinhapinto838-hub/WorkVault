# Work 标题的本地接收方式

WorkVault 的独立应用没有个人 ChatGPT 账户任务列表或下载接口。它不会读取登录 Cookie、会话密钥或 ChatGPT 私有数据库。本地任务清单是可用的替代方式：标题随用户主动保存的成果一起进入授权目录。

## 适用条件

1. 在 WorkVault 的同步中心明确添加一个“专用接收目录”。该目录必须独立于文件库存储目录，不要把 `blobs` 或整个用户目录作为监控源。
2. 在 ChatGPT Work 当前任务已经获得本地写入权限的前提下，要求它把成果及清单写入该目录；是否能写入取决于该任务的实际工具与目录授权。
3. 如果任务无法直接保存到本机，先下载成果，再自己复制文件及清单。WorkVault 不会替任务突破目录权限或下载云端文件。

例如用户选定的接收目录为 `~/Documents/WorkVault-Inbox`，在其中创建：

```text
WorkVault-Inbox/
  CCUS研究/
    task.workvault.json
    outputs/
      研究报告.pdf
      数据表.xlsx
```

`task.workvault.json` 的内容：

```json
{
  "workvault": 1,
  "title": "碳地质封存的跨尺度岩石物理研究",
  "conversation_id": "只有确实知道时才填写真实会话标识",
  "source_url": "https://chatgpt.com/c/真实会话标识",
  "files": [
    "outputs/研究报告.pdf",
    "outputs/数据表.xlsx"
  ]
}
```

**不要直接使用示例中的占位标识或 URL。** 不知道会话标识和链接时，删除 `conversation_id` 与 `source_url` 两行即可。标题应来自当前任务真实标题或用户明确提供的标题，不能根据文件名推测后宣称是真实 Work 标题。

## 清单格式

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `workvault` | 整数 | 必须为 `1` |
| `title` | 字符串 | 任务原始标题，不能为空 |
| `conversation_id` | 字符串 | 可选；只填写可靠的原始会话标识 |
| `source_url` | 字符串 | 可选；仅 http/https 链接，未知则省略 |
| `files` | 字符串数组 | 必须包含 1–1000 个相对于清单目录的普通文件路径 |

清单文件名必须以 `.workvault.json` 结尾，文件内容小于 1 MiB。不接受绝对路径、`..`、符号链接或清单目录之外的路径。目录和文件应完全写入后，再最后保存清单。

该自动解析只发生在已启用的“专用接收目录”监控中。普通手动导入 JSON 文件会作为文件接收，不会把任意 JSON 当作任务清单。下载目录也不会自动把该 JSON 当作已经确认的 Work 来源。

## 可以复制到 Work 的提示词

请先把下方的接收目录与真实任务标题改成你自己的值，再发送给当前任务：

```text
请把本次最终成果保存到我已授权的专用目录：
<我的接收目录>/<本次任务子目录>/outputs/

文件写入完成并确认存在后，请在本次任务子目录中最后写入 task.workvault.json。
清单必须是 UTF-8 JSON，包含：
{"workvault":1,"title":"<本次任务的真实标题>","files":["outputs/<实际存在的成果文件名>"]}

files 列出本次所有实际存在的成果文件，路径相对于清单文件所在目录。
如果你确实能获得当前会话的原始 ID 和链接，可以增加 conversation_id 与 source_url；
如果不能获得，省略这些字段，不要编造。
如果当前工具无权写入该本地目录，请如实说明，并交付可下载成果及清单内容。
不要声称已经完成 WorkVault 账户同步。
```

## 导入结果如何判断

监控会先等待文件连续稳定，再登记。不同文件系统和扫描间隔下，需要经过几个扫描周期；可在同步中心手动扫描，并查看真实日志。

单独出现的成果文件先进入待确认收件箱。有效清单到达并解析成功后，系统按清单中的真实会话标识查找对应项目；已有标识会复用对应项目，缺少标识时会建立独立项目，不仅凭相同标题合并。文件以内容哈希复用实体并关联到清单项目。

清单来源显示为“用户提供任务清单”。这证明的是本地收到用户或任务主动提供的元数据，不是 WorkVault 已通过官方账户接口独立核验。用户仍可修改显示标题；后续同会话原始标题更新不会覆盖用户显示标题。

## 历史官方导出的另一条路线

通过 ChatGPT 官方数据控制或隐私门户取得导出后，使用历史导入向导。当前解析器检测会话数组、常见容器键 `conversations` / `chats` / `items`、`id` / `conversation_id` 和 `title` 字段。它不是所有未来导出格式的保证，也不验证导出文件的数字签名。

当前仅在会话顶层 `type` 或 `mode` 明确等于 `work` 时标为 Work；不能判定的会话保留为待确认候选项目，不会自动计入正式 Work 档案。导出中的附件 `file_id`、可识别文件元数据和 `sandbox:/mnt/data/` 引用仅生成“需要补充原文件”的索引。即使导出目录里有附件实体，当前版本仍要求手动选择原文件并关联到项目，避免不可靠的名称匹配。

导出中的会话 ID 用于关联，而相同标题始终不足以认定是同一任务。未知 JSON 结构会明确报错，不会伪造导入成功。
