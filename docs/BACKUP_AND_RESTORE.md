# 手动备份与恢复

没有自动定时备份。设置或首页“创建手动备份”，选择保存目录，按需勾选包含 AI 索引。备份生成独立文件夹（不是依赖服务器的云快照），包含 SQLite 一致性快照、所有已登记 blob 与历史版本、关系/来源/分类/标签/配置，以及版本化 SHA-256 清单。

临时 `.partial` 文件夹写完、逐项校验后才成为正式备份；失败不会标为成功。DeepSeek 密钥在系统 Keychain，不在备份里。默认排除正文 AI 索引；排除时清理快照中的索引数据，保留重新构建能力。工作副本中未登记为版本的外部编辑不是正式历史版本，重要编辑请先保存登记再备份。

## 校验和恢复

1. 打开设置中的“校验 / 恢复备份”，选择具体备份文件夹。
2. 查看备份版本、文件/项目概要与校验结果。哈希不一致或缺少数据库则拒绝恢复。
3. 选择恢复父目录。界面创建一个新的 `WorkVault-Restored-时间戳` 子目录，避免覆盖现有库。
4. 阅读确认提示后恢复。系统校验所有实体、数据库关系和外键，原库继续可用。
5. 如需使用恢复库，点击“选择已有文件库”，选择新恢复目录。当前库保留，可随时切换回来。
6. 恢复后重新配置 Keychain 密钥。若未备份 AI 索引，按需手动重建。

较新 schema/未知备份版本会被拒绝，不能强行降级覆盖。不要手工改 manifest 后把它当成可信完整性凭据；SHA-256 用于检测意外损坏，不是对恶意篡改者的数字签名。

应将重要备份另存到外置磁盘等独立介质。本机同一磁盘上的备份不能抵御整盘损坏。应用不会自动上传备份。
